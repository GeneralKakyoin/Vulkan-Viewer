---
name: doc-update
description: Update continuity docs after meaningful progress. Use after implementation, protocol research, milestone changes, or architecture clarification.
---

## Read first
- AGENTS.md
- docs/MASTER_PLAN.md
- docs/CURRENT_STATE.md
- docs/HANDOFF.md
- docs/TASKS.md
- the just-completed change summary

## Goal
Keep project continuity reliable across chats and agents.

## Do
1. Update docs/CURRENT_STATE.md with:
   - what now works
   - current blocker
   - next step
2. Update docs/HANDOFF.md with:
   - last completed work
   - immediate next task
   - files likely involved
   - constraints
3. Update docs/MASTER_PLAN.md only if:
   - milestone/state changed materially
   - roadmap understanding changed materially
4. Update docs/TASKS.md if task ordering changed.

## Output
Return:
- which docs changed
- what was updated in each
- whether MASTER_PLAN changed and why

## Rules
- Keep wording concise.
- Reflect actual state only.
- Do not speculate.
